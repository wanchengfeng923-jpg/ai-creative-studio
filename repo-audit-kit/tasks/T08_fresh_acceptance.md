# T08：新会话独立验收

## 本轮目标

验证一个新会话是否真的能接手项目，并核对审计是否覆盖约定范围。这是本轮任务，应在 T07 之后新开的会话执行。

## 输入顺序

先读有效规则、短状态、验收问题和当前正式文档。暂不读取此前报告中的答案与“整理成功”结论。T01 应已把问题单独保存在 acceptance-questions.md。

## 执行

1. 从当前资料独立回答验收问题：项目怎样运行、指定功能在哪里修改、应遵守什么约束、当前未完成与阻塞是什么、怎样验证。
2. 核查本轮实际加载的规则来源，记录无法观察的限制；为回答附上当前文件证据。
3. 保存独立答案后，再查原任务的证据和验收标准，比较遗漏、错误和不必要的检索成本。
4. 用程序化筛选或分组读取核对全局台账：清单与覆盖匹配、任务依赖完整、未解决事项有去向、必要检查已通过。不要一次加载所有报告来做“全局总结”。
5. 若范围过大，将全局台账核对拆成多个 T08 子任务，并增加最终汇总任务；最后汇总引用已验收结果和剩余缺口。
6. 发现问题时登记具体失败及修复任务，保持 active 或 waiting。修复后由新的会话再次验收，不通过在本轮反复提示答案伪装首次接手成功。

## 最终输出

独立答案与证据、范围验收结果、未解决发现、必要验证状态和最终报告入口。满足全部完成条件才能标记 complete；有明确验证限制时如实区分 complete_with_limits 或 waiting。

新会话不等于统计意义上的独立模型。它主要检验资料可接手性；不能据此宣称发现所有缺陷或证明不存在偏差。

保存最终报告和状态后结束，不重新启动全仓审计。以后新增功能引起变化时，再开展对应范围的增量检查。
