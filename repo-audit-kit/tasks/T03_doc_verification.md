# T03：核对一组文档与实现

## 本轮目标

独立核对 QUEUE 指定文档组中的事实、规则声明、当前管理入口和对应实现。此轮生成可审查发现，不直接修订正式文档；历史全文不在本阶段展开。

## 前提与输入

相关 T02 实现范围已有可用证据；不足时追加依赖任务。仅读本组文档、相关报告片段及核对所需的当前源码和配置。

## 执行

1. 将文档中的路径、命令、接口、模块职责、前置条件、兼容要求和完成状态拆成可检查声明，并把每组声明映射到真实文件与 T02 证据。
2. 对照当前实现、测试与配置；重要结论回查原始文件，不能只转述 T02 总结。
3. 记录过期描述、相互冲突、重复规则、失效引用、缺少入口和完成状态缺乏证据等问题。
4. 分清已实现、已验证、已发布；分清实际行为与预期业务意图。冲突不能自动裁决为“代码正确”。
5. 对长历史文档，先记录分段范围与未完成事项候选，不让一轮无限读完整项目历史。后续 T06 仍须对迁移内容逐项核对。
6. 给每项问题提出具体处理建议及验证办法，指出依赖哪个模块、规则或用户判断。

## 输出与完成条件

范围内有效声明已核对或明确标记未核对原因；每项重要发现有来源、版本、影响、证据状态和处理建议。补充本组输入给 T04、T05 或 T06 的关系。

交接后结束。不要把“已核对文档”标成“文档已修正”，也不能以源码盘点报告或 README 阅读记录替代本阶段报告。
