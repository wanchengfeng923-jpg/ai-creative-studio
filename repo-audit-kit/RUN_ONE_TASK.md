# 每次新会话的统一入口

你正在执行用户要求的多会话仓库整理。**本轮只完成一个具体子任务；结束前落盘交接，不继续下一个子任务。**实际权限仍以用户指令、已有授权和有效项目约束为准。此文件是任务说明，不用于改写指令优先级。

## 1. 恢复状态并选定任务

1. 识别当前仓库与本任务包真实路径，先遵守当前环境已生效的规则。
2. 若任务包中没有 `ACTIVE_RUN.md`，检查默认 `docs/repo-audit/STATE.md` 是否存在，并确认它是否属于当前仓库的这次审计。若已存在则恢复，不能重新初始化覆盖；若不存在，执行 `tasks/T01_baseline.md`。
3. 若有 `ACTIVE_RUN.md`，读取其中实际审计目录；再读其 `STATE.md`。相对路径以仓库根为基准。不要扫描无关项目的状态。
4. 如果 STATE 标明 complete，检查该状态对应的源码和规则是否发生变化。没有相关变化则报告此前已完成并结束；有变化则只建立或执行必要的增量复核。
5. 按 QUEUE 查询未完成任务，优先恢复中断任务；否则选择依赖已满足、范围明确的一条任务。队列很大时用结构化读取或过滤，只向上下文返回候选与依赖行。
6. 确认当前提交、未提交差异和相关文件是否仍匹配该任务的基线。审计自身的记录写入不使业务结论自动失效，但被整理的规则、文档和代码变化必须计入。
7. 读取该任务的任务卡、所需报告片段和源文件。没有必要时，不读取全部任务卡、完整研究指南、全部历史或整张发现表。
8. 简短说明本轮任务 ID、范围、允许修改的对象和完成条件，然后执行。范围未记录清楚时，先用已有事实补齐；无法自行判定的业务或权限缺口才询问。

9. 每轮开始先用结构化方式统计 `QUEUE.csv` 中 T01-T08 各阶段任务数量和状态。默认阶段门槛为：全部纳入范围的 T02 完成，或明确标为 `not_applicable`/`split` 并记录去向后，才能开始 T03；全部 T03 完成或有明确限制后，才能开始 T04。仅在源码盘点中顺手阅读文档，不能代替 T03 报告。

10. 若现场报告已证明父任务的一部分完成、但仍有明确残余范围，保留原报告和证据，将父任务标为 `split` 并在 `children` 列出残余任务；不要重跑已完成部分，也不要把残余代码修复混入文档审计。程序修复、重构和部署类后续事项保留来源并移出当前文档整理验收依赖。

若没有可执行任务，但还有阻塞或未分配范围，报告具体缺口并结束；不能把“没有 ready 任务”当作“全部完成”。

## 2. 本轮共同要求

- 本次范围为盘点、文档与规则整理。代码 Bug 修复、重构、依赖升级、发布、部署和新增 CI 等工作只有已经获授权才执行，否则列为后续事项并标记 deferred，不作为当前 T03-T08 验收依赖。
- 保留用户未提交改动。先记录，再操作；不自动 reset、stash 或删除来获得干净工作区。
- 重要结论记录来源、版本及“已证实 / 推断 / 待确认”。代码说明实现，不能独自裁决业务意图。
- 清点、阅读、交叉核对和运行验证分别记录；没运行的命令不能写成通过。
- 发现超出本轮范围的问题，只保存证据与后续任务，不在当前会话追遍全仓。
- 用户已明确优化的 `progress.md` 本轮不重新审计、优化、迁移或验证；保留其现状和既有读取安排，不新增相关任务。
- 已获授权且前提明确的动作直接完成，不逐步要求确认。需要判断的问题集中记录，不阻止其他独立任务继续。
- 规则改动保留有效约束的含义、作用域与例外；不能改规则为自己解除限制。
- 不主动使用多 Agent。本方案默认由用户按顺序开新会话；额外并行仅在用户或有效项目要求明确授权时考虑。

## 3. 工作过大时怎样切分

先选可独立检查的边界：一个模块、一条流程、一组相关规则或一批历史记录。若仍过大，为未完成范围增加子任务和依赖，并保留原任务的已完成证据。

父任务使用 split 状态，children 中列出子任务。只有所有子任务已完成或被合理判定为不适用，父任务才可转为 done；下游依赖在此之前不能视为满足。拆分不得遗漏原范围或把困难部分从验收中删除。

若残余属于延期的程序修复，不应伪造一个已执行的审计子任务，应保留来源并标为 `not_applicable`/`deferred`，把必要的文档核对并入真实 T03。

在每个重要小结形成时更新相关记录。不要在第一次快用完上下文时才开始写全部报告。若无法观察真实 token 使用量，不声称知道精确余量。

## 4. 本轮结束必须保存

按 `HANDOFF_FORMAT.md` 完成以下动作：

1. 保存本轮证据和结果到 reports 中该任务的报告，复用同一任务报告更新现状。
2. 更新本轮涉及的覆盖与发现记录，保留来源，不复制全部台账到报告。
3. 更新 QUEUE 的状态、依赖、剩余范围与下一动作；阻塞和未验证项保留。
4. 更新 STATE 为短的当前状态与唯一下一步入口。旧过程详情放到对应报告，不能无限追加到 STATE。
5. 核对必要文件已保存、引用存在、任务状态与报告一致，工作区没有被本轮留下已知的断链或半迁移状态。若无法恢复一致，明确登记阻塞和恢复动作。
6. 输出本轮完成内容、修改文件、检查结果、限制与下一任务，然后结束本轮。

协议修订轮的最小交付是：更新统一入口/任务卡、真实队列、短 `STATE.md` 和一份修订报告；不得借协议修订开始下一个业务盘点或程序修复。

若当前 `STATE.md` 设置了阶段停止点，完成该阶段全部任务并保存交付后立即停止，不自动选择后续阶段。

中途被用户打断后恢复时，先比较真实差异与报告，不盲目重做，也不能假设上次已完成写入。没有写权限时，在回复中完整给出交接文件内容或补丁，并明确需要先保存后才能可靠开新会话。

## 5. 用户每轮应看到的简短结果

- 本轮：任务 ID 与范围。
- 完成：具体结果与对应报告入口。
- 验证：通过、失败、未运行及原因。
- 遗留：待完成范围或需要用户判断的具体问题。
- 下一轮：建议任务 ID；继续使用本入口即可。

只有 T08 通过并核对全局状态后，才输出“约定范围已完成”；否则输出“本轮完成”或“本轮已交接”。
