## 已核实关系

1. 默认直接运行 `creative_studio.app` 时，`create_application()` 使用 `CREATIVE_STUDIO_DATA_DIR` 或仓库 `data/`；composition root 默认网关 URL `127.0.0.1:8780`，只有 `CREATIVE_STUDIO_AI_V2_LIVE=1` 才装配 HTTP text/image gateway，否则没有注入模型时 fail closed。网页 host/port 默认 `127.0.0.1:8775`。
2. launcher 是另一条 composition root：固定网页 8775、网关 8780，并在 `_environment()` 显式注入 `CREATIVE_STUDIO_AI_V2_LIVE=1`、控制令牌、数据/图片/job 目录和 gateway URL，然后启动 `chat2api/main.py` 与网页进程。由此新增 F-010：文档/规则中“默认 candidate/fail-closed、需显式 live 审批”只适用于直接 app 或描述性入口；点击 launcher 启动实际会进入 live 配置，是否把 GUI 点击视为生产批准没有独立证据。
3. chat2api 默认监听回环 8780；图片 job 端点通过控制令牌保护并使用 `CHATGPT_IMAGES_DIR`/`CHATGPT_IMAGE_JOB_DIR`，text `/v1/chat/completions` 的安全边界主要依赖回环同机信任。AI v2 adapters 只接受回环/同源图片下载并传递 conversation/parent 游标；真实外网、进程和多用户部署未验证。
4. launcher 的代理桥固定 7896，Clash 候选端口来自配置/默认列表；这与 T02-003/部署文档一致，但不构成网络出口成功证据。公网手册的 `0.0.0.0:8775`、HTTP 和 live 注入是受控历史方案，不能覆盖 AGENTS 的高风险门禁。
5. F-003（store Protocol 不完整）与 F-004（batch fingerprint 固定 v1）确实跨 use-case/store/application；当前所有 registry 版本都是 v1，问题未在现状触发，但升级时会影响替换 seam/去重语义。F-005/F-006/F-007/F-008/F-009 的证据互相加强：备份边界、registry hash、文档/部署/审批快照都不能在当前工作树宣称已完成。
