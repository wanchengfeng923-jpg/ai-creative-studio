## 已证实结论

1. ADR-0001/0002/0003/0004 均 `Accepted`，ADR-0005 为“Accepted for implementation; production Prompt/cutover approval remains separate”。它们固定了白名单公开投影、标签同步、轮播共享 planner/后台 operation、空标签和 v2 会话/重试边界；条目包含替代关系、验证和回滚约束，可作为 T04 的长期约束来源。
2. ADR 与当前实现大体兼容：公开投影白名单、v2 三字段输入、图片稳定 request key/attempt、未知供应商结果不创建新会话、真实 AI/图片/浏览器/多进程仍未验证，均有源码/测试或 T02 证据支持。ADR 不是“已发布/已生产验收”证明。
3. 新增 F-009：同一受限 handoff/spec 文档的审批状态冲突。`2026-09-06-ai-v2-next-session-handoff.md`、`readiness-baseline.md` 明确三份 Prompt 仍 candidate/caller=null、不得默认 live/需单独审批；`ai-v2-production-cutover-handoff.md` 与 `ai-v2-text-first-preview-design.md` 的索引/当前结论又声称已绑定 production caller/完成正式切换前准备。当前 registry 文件虽然标 production，但 static/carousel hash mismatch（F-006），且当前测试并未形成可加载的 production 证据。因此不能仅凭 handoff 选一方为当前事实。
4. `docs/superpowers/specs/2026-09-04-ai-v2-text-first-preview-design.md` 明确预览不请求生产 API、不写库、不代表正式 caller；`2026-09-05-ai-v2-production-integration.md` 要求 fail-closed、零真实调用、不得宣称 production readiness。研究流程文档则要求变更卡、临时库/fake、备份恢复和真实外部能力单独授权。这些是有效约束，应在后续整理中保留。
5. 研究文档多为外部一手来源和工程建议，不裁决当前仓库实现；代理/VPN 研究明确需要逐层实测，不能把静态连通性或历史截图升级为部署通过。

## 推断与待确认意图

- handoff 文档很可能来自连续的不同切换阶段；需要 T04 按 commit/工作树/报告时间建立唯一证据链，再决定哪些 handoff 保留为历史、哪些作为当前入口。
- 不应将“Accepted for implementation”自动解释为 production approval；需要明确审批记录、registry 可加载性和 caller reachability。
