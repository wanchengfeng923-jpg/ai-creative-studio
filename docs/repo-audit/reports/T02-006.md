## 已证实结论及证据

1. 配置实际文件包括：`config/ai_v2/prompts/registry.json` 与 3 个文本模板；`config/ai_v2/schemas/{narrative-text,static-text,carousel-text}-v1.json`；`config/evals/ai_v2/expected-hard-constraints.json`、30 行 `prompt-cases.jsonl`、`reports/candidate-contract-evidence.v1.json` 和其 README；另有 `config/creative_tag_options.json`。
2. `src/creative_studio/ai_v2/prompt_registry.py` 从 registry 相邻目录静态读取模板，限制路径 containment、UTF-8、SHA-256、三种占位符、lifecycle/caller、正整数 max_model_calls，并在不匹配时 fail closed。`schema.py` 仅允许三个已知 schema/v1，从仓库配置读取并执行最小无依赖校验及 carousel 连续帧约束。
3. registry 当前声明三个 `creative.ai_v2.*@v1` production caller，均 `max_model_calls=1`、输入 `AiV2Input.v1`，输出分别为 narrative/static/carousel v1。实际 `Get-FileHash`：narrative 与 registry 一致（`70b3...f0e4e`）；static 实际为 `A956...AF65D`，registry 为 `c820...139b`；carousel 实际为 `FB2B...B6FE9`，registry 为 `84c2...fb08`。默认 `AiV2PromptRegistry()` 因此抛出 `AiV2PromptRegistryError: v2 prompt template hash mismatch`，复现既有 F-006。
4. eval 资产为 30 cases（narrative/static/carousel 各 10）；硬约束定义输入三字段、输出数量/私有字段、单次文本调用和失败策略。候选报告声称 deterministic fake、29/29 contract outcomes passed、private leak 0、real model quality `not-run`，且报告中的 registry 三项仍为 `candidate`、`caller=null`，hash 为另一组值；它不能直接证明当前 production registry 可加载或真实质量。
5. 用例通过 `NarrativeTextUseCase`、`StaticTextUseCase`、`CarouselTextUseCase` 调用 `AiV2PromptRegistry.get()`；应用组合根默认构造 registry。配置/评测没有动态 import 或执行 prompt 文本的证据。
