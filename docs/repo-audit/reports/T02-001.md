## 已证实结论及证据

### 1. 入口与依赖方向

`app.py:create_application()` 是唯一组合根：显式构造 `SqliteAiV2Store`、`AiV2Application` 和 `AiV2HttpApi` 的懒加载工厂；默认 `CREATIVE_STUDIO_AI_V2_LIVE` 未开启时拒绝构造真实模型，测试可注入 `TextModelPort`/`ImageModelPort`。`StudioHandler` 先完成认证、CSRF 和项目归属检查，再把 v2 路由交给 `AiV2HttpApi.dispatch()`。模块未从 `ai_v2` 反向依赖旧生成模块，`boundary.py` 和 `test_ai_v2_boundary.py` 对此有静态守卫。

### 2. 输入、Prompt、schema 和用例

- `input_contract.py` 将请求收口为 `task_description`、`aspect_ratio`、`creative_tags` 三字段，去重/去空标签，忽略编辑器专用 `visual_carousel_rounds`，并按项目类型及 `visual_carousel=是` 选择 `narrative`、`static` 或 `carousel`。
- `prompt_registry.py` 只允许仓库内已登记模板，校验 UTF-8、文件 hash、三变量占位符、生命周期和 caller；`compile_prompt()` 执行单次字面替换。
- `schema.py` 只加载三个已知 `*-v1` schema；除 JSON Schema 子集外，轮播额外校验帧/私有 prompt 数量和连续 index。
- 当前 registry 三项均为 `production`、`max_model_calls=1`，分别绑定 `NarrativeTextUseCase.generate`、`StaticTextUseCase.generate`、`CarouselTextUseCase.generate`；`production_gate.py` 检查 caller 可达、schema 对齐和唯一性。

### 3. 三条文字生成路径

- `NarrativeTextUseCase.generate()`：一次文字模型调用，保存五个故事、公开投影；失败写 `ai_v2_runs.error_code`。
- `StaticTextUseCase.generate()`：一次调用保存三案和每案一帧 `pending`；图片只由 `request_image()` 按需启动。
- `CarouselTextUseCase.generate()`：一次共享规划调用保存三套路线和逐帧私有指令；支持固定 2-5 帧或 AI 决定，随后 `request_frame()` 只按序推进当前帧。
- 三条路径都构造 `TextRequest`（prompt、schema、model、幂等键），先解析/校验，再交给 store 保存；异常转换为带 `error_code/field_path/retryable` 的用例错误。

### 4. 图片 seam、状态与恢复

`model_ports.py` 定义 typed `ImageRequest`、`ImageContinuation`、`ImageSubmission`、`ReconcileRequest` 和 `ImageArtifact(bytes, MIME, sha256)`。`ImageGatewayAdapter` 将其映射到 `/v1/images/jobs`，限制回环/同源图片 URL，保留真实 MIME，并对瞬时提交失败做一次同 request id 重试。`ImageWorker` 读取 attempt 自身的 provider job 对账，成功时调用 store 的原子完成；轮播后续帧携带上一帧成功 artifact 作为参考图。`image_state.py` 提供纯状态迁移和稳定逻辑键。

### 5. canonical SQLite 存储和公开投影

`migrations.py` 只创建 `ai_v2_runs`、`ai_v2_schemes`、`ai_v2_frames`、`ai_v2_image_sessions`、`ai_v2_image_attempts`、`ai_v2_artifacts`、`ai_v2_adoptions` 及索引，并为旧库补 `aspect_ratio`。`store.py` 负责批次上限（最多两批）、attempt/session 原子 claim、幂等 request key、前序帧门禁、过期/失败重试、游标单调性和 artifact/cursor 原子提交。

`projection.py` 以白名单重建 `public_run`、`public_scheme`、`public_image_state`；`execution`、prompt、cursor、job id、本地路径和堆栈不会进入浏览器 DTO。应用层的 `history`、`run`、`adopt`、`image_attempt` 和图片 bytes 入口均经过该投影或显式 MIME 检查。

## 推断与待确认意图

- `AiV2Store` Protocol 目前只声明少量核心方法，而 `AiV2Application`/三个 use case 实际依赖更多读取、保存、对账方法；运行时由 `SqliteAiV2Store` 满足，但静态 seam 文档不完整。记录为后续跨模块/设计复核，不在本轮改接口。
- `AiV2Application.generate()` 为自动计算已有批次时固定传入 `prompt_version="v1"`，而三个 use case 从 registry 读取 `spec.version`；当前所有 registry 都是 v1，因此现状未失败，但版本升级时可能造成批次 fingerprint 语义漂移。留给 T04-001 复核。
- `run()`、`adoption()` 等 facade 方法本身不承担用户归属判断，依赖 `StudioHandler._require_v2_route_access()`；直接调用 facade 的授权责任边界需在 T04-001/T04-002 明确，不将 HTTP 测试结论扩大为所有调用方。
