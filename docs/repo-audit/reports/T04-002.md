## 已核实关系

1. 输入契约由 `AiV2Input`/三字段 HTTP body 约束，schema loader 只允许 narrative/static/carousel v1；store 保存 canonical JSON、私有 execution prompt、image session/attempt/cursor，公开读取再经 `public_run`/`public_scheme`/`public_image_state` 白名单重建。
2. projection 明确丢弃 `execution`、`image_prompt(s)`、conversation/parent cursor、gateway job id、本地路径和 raw response；公开 image state 只暴露安全状态、attempt/error 摘要和由 attempt id 生成的图片 URL。privacy/projection tests 与前端 contract tests 覆盖这些禁止字段。
3. `static/app.js` 只消费公开 `schema_version`、items、title/description/core_subject/layout、frames/index/description、image_state/status/url/error，以及 v2 history/adoption/image endpoints；测试禁止脚本出现私有字段和旧 adoption/generation 路由。轮播前端按公开 frame description/index 和单帧状态轮询，符合 ADR-0003/0005。
4. HTTP handler 在 v2 generate/history/adopt/adoption/run/scheme/queue/attempt/image 路径先将资源解析到 project，再执行 owner/admin 检查；application facade 也对 project provider 做存在性检查。直接调用 facade 的授权仍由 HTTP caller 负责，属于 F-003 相关边界，不把应用集成测试扩大为任意调用方授权证明。
5. adoption snapshot 通过 `public_run` 生成，项目投影保留中立 `adoption` 结构；不会把 store 私有 canonical 直接返回。当前未发现新的已证实隐私泄露；真实浏览器、真实历史脏数据 scrub/apply 和多用户竞态仍未验证。

## 推断与待确认意图

- 已证实公开投影与路由归属检查形成两层边界，但 `AiV2Store` Protocol 只声明 reserve/claim 等少量方法，不能单独证明所有 facade caller 的授权或替换能力（F-003）。
- 业务上“公开 DTO 可被前端消费”已由静态契约和投影测试支持；真实浏览器渲染、真实脏数据 scrub/apply、多用户竞态仍是待确认事项。
- registry/hash/lifecycle 冲突（F-006/F-007/F-009）不改变本任务的字段映射结论，但阻止端到端 live 生成被视为当前有效证据。
