## 已证实结论及证据

### 1. 组合根与 HTTP 边界

`create_application()` 构造 `StudioRepository`、`AuthService` 和 `ProjectProjection`，将 `database_path`、图片/上传目录和可选 clock/fake seam 注入应用容器；AI v2 采用懒加载工厂。`StudioHandler` 在业务路由前执行 session、CSRF、密码变更状态和项目 owner 检查，普通用户只能看到自己拥有的项目，管理员可跨项目访问。上传文件先按项目目录生成随机存储名，再记录 SHA-256、MIME 和提取状态；公开响应统一经过 `ProjectProjection`。

### 2. 认证与会话

`auth.py` 使用固定迭代次数的 PBKDF2-SHA256、随机 salt 和 URL-safe bearer/CSRF token；登录失败使用 dummy hash 维持未知用户路径的密码校验成本，并由仓储按用户名/IP 维护 15 分钟窗口、5 次锁定和审计记录。会话只在 SQLite 保存 token/CSRF 摘要，支持 12 小时 idle、7 天 absolute 过期，touch 不超过 absolute expiry；停用用户、改密和显式注销会撤销会话。管理员只能创建/管理普通用户，最后一个活跃管理员不能停用。

### 3. SQLite 仓储与所有权

`repository.py` 以 WAL、外键和 `BEGIN IMMEDIATE` 初始化/迁移 `projects`、`project_files`、`users`、`sessions`、`login_attempts`、`audit_logs`，当前 `SCHEMA_VERSION=3`；旧项目表按需补 `owner_user_id`，项目文件按需补摘要、MIME、提取状态和安全摘要列。bootstrap admin 仅允许空账号库首次创建，并会认领无主项目；后续调用保持幂等并继续补领新建的无主项目。项目字段有固定白名单、长度/枚举归一化，文件元数据和审计 metadata 经过边界清洗。旧生成相关表不会被新仓储创建、迁移、读取或删除。

### 4. 备份、恢复与保留计划

`backup.py` 对 SQLite、`images/`、`uploads/` 建立 `backup-manifest.v1`，记录大小和 SHA-256；dry-run 不创建输出，正式备份拒绝写入源目录。恢复先校验 manifest 路径、大小和摘要，在临时 staging 目录复制并复核，再检查 `project_files` 与旧成功图片引用，最后原子替换到目标目录。保留计划只列出最新 N 个有效备份和可删除候选，不执行删除；无效 manifest 进入 `invalid`。

## 推断与待确认意图

- `create_application(environment=...)` 只用传入 mapping 读取 AI/认证相关变量，但数据根目录仍直接读取进程 `os.environ`；显式路径参数可绕开该差异。是否要求 environment seam 同时覆盖数据目录，留给后续部署/组合根复核，不在本轮修改。
- 仓储构造器提供 `clock`，但认证、会话、审计和多数项目更新路径仍直接调用模块级 `now_text()`；当前测试不依赖统一虚拟时间。若需要确定性过期/并发测试，应在后续设计中统一时间来源。
- `ProjectProjection` 的 `owner_user_id` 是公开 DTO 字段；当前 handler 已先完成 owner 检查，但其他直接调用投影的调用者需由 T04-002 复核其公开边界。
