# 领域文档

本仓库采用单上下文领域文档布局。工程技能探索代码库时按以下规则消费领域文档。

## 在探索之前阅读

- 仓库根目录的 `CONTEXT.md`
- `docs/adr/` 中与当前工作区域相关的 ADR

如果这些文件不存在，静默继续，不把缺失视为错误，也不建议提前创建。`domain-modeling` 技能会在术语或决策确实需要记录时延迟创建它们。

## 文件结构

```text
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-example-decision.md
│   └── 0002-another-decision.md
└── src/
```

## 使用术语表的词汇

当输出命名领域概念时，包括 issue 标题、重构提案、假设或测试名称，应使用 `CONTEXT.md` 定义的术语，不使用术语表明确排除的同义词。

如果所需概念尚未出现在术语表中，应重新检查是否使用了项目之外的语言；如果确实存在领域空白，则记录并交由 `domain-modeling` 处理。

## 标记 ADR 冲突

如果输出与现有 ADR 冲突，应明确指出，不得静默覆盖。例如：

> 与 ADR-0007 矛盾——但值得重新讨论，因为……
