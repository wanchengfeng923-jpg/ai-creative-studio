# AI 创意工作台部署控制面板规则

状态：首版已实施，服务器人工验收待完成

确认日期：2026-09-09

适用系统：Windows Server

开发仓库：`D:\code\ai_creative_studio`

服务器目录：`E:\AI-Creative-Studio`

## 目的

部署控制面板为 AI 创意工作台提供一个独立的 Windows 桌面运维入口。它保留现有启动器，负责组织启动前检测、公网上下线、端口诊断、日志查看、版本更新和代码回滚。

目标用户不需要记忆 PowerShell 命令。正常流程应当是：打开面板，打开现有启动器并启动服务，完成启动前检测，上线公网，完成上线后检测；停止使用时从面板执行全部下线。

本文档同时是面板的设计规格和长期维护规则。修改面板行为、端口、进程归属规则、发布流程或安全边界时，必须同步检查并更新本文档。

## 范围

首版包含：

- 打开现有 `启动AI创意工作台.bat`。
- 查看启动器、Web、AI 网关和代理桥状态。
- 检查 `7896`、`8775`、`8780` 的监听地址、PID、进程名称、项目归属和健康状态。
- 执行启动前检测。
- 将项目 Web 从本地监听切换为公网监听，并管理指定的 Windows 防火墙规则。
- 执行上线后检测并打开工作台。
- 完整关闭 Web、AI 网关、代理桥和启动器，并撤销公网放行。
- 检查发布 ZIP、执行服务器代码更新和选择已有回滚点回滚。
- 查看和打开相关日志、部署文档及日志目录。

首版不包含：

- Windows 开机自动上线或无人值守自动恢复公网。
- HTTPS、正式域名、反向代理、外部限流或云防火墙管理。
- 任意端口映射、任意防火墙规则编辑、任意命令执行或强制结束所有 Python 进程。
- 在服务器上构建发布包。发布包继续由开发电脑的 `scripts\build_release.ps1` 生成。
- 修改或显示 `chat2api\.env` 中的令牌、Cookie、密码或完整代理地址。
- 修改数据库、图片、上传文件或用户信息。

## 技术方案

面板使用 Python 3.11 和 Tkinter/ttk 实现，通过项目现有 `.venv` 运行。系统级检查和操作通过受控的 Python 接口及 PowerShell 子进程执行。面板不启动新的 HTTP 管理服务，也不增加管理端口。

建议模块边界：

```text
启动部署控制面板.bat
        -> 请求一次 Windows 管理员权限
deployment_panel.py
        -> 窗口、状态展示和用户动作编排
deployment_control/
        service_manager.py
        port_inspector.py
        health_checker.py
        firewall_manager.py
        release_manager.py
        operation_log.py
```

各模块职责：

- `deployment_panel.py` 只管理界面状态、后台任务和按钮动作，不直接拼接系统命令。
- `service_manager.py` 负责启动器启动、项目进程归属、Web 切换和完整停止。
- `port_inspector.py` 负责读取监听端口及对应进程证据，不执行停止操作。
- `health_checker.py` 负责 Web、网关和公网健康检查，并返回结构化结果。
- `firewall_manager.py` 只管理本文规定的 `8775` 防火墙规则。
- `release_manager.py` 调用现有 `scripts\server_release.ps1`，不复制发布、校验和回滚算法。
- `operation_log.py` 负责结构化操作记录和敏感信息脱敏。

界面中的耗时工作必须在后台线程执行。Tkinter 控件只在主线程更新，防止检测、网络访问、依赖安装或发布操作卡住窗口。

## 权限模型

`启动部署控制面板.bat` 在启动时请求 Windows 管理员权限，只弹出一次 UAC。面板同时验证当前进程是否已提升权限。

- 已获得管理员权限：允许执行检测、上下线、项目进程停止、更新和回滚。
- 未获得管理员权限：只允许查看状态、日志和文档；禁用所有会修改进程、防火墙或代码的按钮。

权限状态必须在主页面持续可见。面板不得用静默失败掩盖权限不足。

## 固定运行边界

| 组件 | 端口 | 允许监听地址 | 公网放行 | 管理原则 |
|---|---:|---|---|---|
| 代理桥 | `7896` | `127.0.0.1` | 永不允许 | 仅在当前代理配置需要时运行 |
| Web | `8775` | 本地阶段 `127.0.0.1`；公网阶段 `0.0.0.0` | 仅公网阶段允许 | 必须先确认项目归属 |
| AI 网关 | `8780` | `127.0.0.1` | 永不允许 | 健康不代表真实 AI 请求成功 |

固定防火墙规则名为 `AI Creative Studio Web 8775`。面板只能创建、启用、检查、禁用或删除这一条规则，不能操作其他应用的规则。

公网地址默认为 `http://42.194.220.18:8775/`。项目根目录根据面板文件位置解析，禁止在运行逻辑中写死开发电脑的 `D:` 或服务器的 `E:`。

## 状态模型

面板使用以下顶层状态：

```text
全部关闭
  -> 启动器已打开
  -> 本地服务启动中
  -> 本地服务就绪
  -> 公网切换中
  -> 公网运行中
  -> 下线中
  -> 全部关闭
```

任一步骤都可以进入“存在异常”。异常状态必须保留已观测到的真实端口和进程信息，不能为了显示简洁而把部分运行误报为全部关闭。

按钮启用规则：

- 服务未启动时禁止“上线公网”。
- 启动前检测存在关键失败时禁止“上线公网”。
- 公网运行时禁止重复上线。
- 发布包未完成检查时禁止“执行更新”。
- 服务未全部停止时禁止修改代码或回滚。
- 操作进行中时禁用会产生冲突的按钮，但保留日志查看。
- 面板窗口关闭不触发自动下线；完整停止只能由“全部下线”执行。

## 页面和功能

### 运行控制

主页面显示顶层状态、管理员权限、三个端口的简要状态和最近一次操作结果。

“打开启动器”：

- 运行现有 `启动AI创意工作台.bat`。
- 检测到现有启动器时不重复启动。
- 用户仍在现有启动器中点击“启动”，由启动器读取配置并拉起本地服务。

“刷新状态”：

- 重新读取进程、端口、防火墙和健康接口。
- 只读执行，不改变服务状态。
- 在后台执行并显示“正在刷新状态”或“状态已刷新”；只暂时禁用刷新按钮，不锁住其他控制按钮。
- 一次刷新复用同一份进程快照，不得对每个端口重复枚举 Windows 进程。

“启动前检测”：

- 检查 `chat2api\.env` 是否存在，但不读取或展示其内容。
- 检查 `.venv\Scripts\python.exe`、数据库、图片、上传和任务状态目录。
- 检查 `8780` 网关健康接口。
- 检查 `7896` 代理桥是否符合当前运行需要。
- 检查 `8775` Web 健康状态和项目归属。
- 检查三个端口没有未知进程冲突。
- 输出通过、警告或失败；关键失败阻止上线。

“上线公网”：

- 要求最近一次启动前检测通过，并在执行前重新检查关键条件。
- 只停止已确认由本项目启动器拉起的本地 Web。
- 使用同一项目虚拟环境和启动器等价的环境变量重新启动 Web，唯一监听差异是 `CREATIVE_STUDIO_HOST=0.0.0.0`。
- 从 `chat2api\.env` 读取运行所需控制令牌时只在子进程环境中传递，不写入界面、命令行参数或日志。
- 保持 AI 网关为 `127.0.0.1:8780`，保持代理桥为 `127.0.0.1:7896`。
- 创建或启用固定的 `8775` 入站防火墙规则。
- 自动执行上线后检测。任何关键步骤失败时停止后续步骤并显示当前真实状态。

“上线后检测”：

- 确认 `8775` 监听 `0.0.0.0`。
- 确认 `8780` 和运行中的 `7896` 仅监听回环地址。
- 检查固定防火墙规则的方向、协议、端口和启用状态。
- 检查本机 Web 和网关健康接口。
- 尝试通过配置的公网地址访问 Web 健康接口；失败时区分本机服务故障和外部访问故障。
- 只有关键项全部通过才显示“公网运行中”。

“打开工作台”：

- 公网运行中时打开公网地址。
- 仅本地服务就绪时打开 `http://127.0.0.1:8775/`。
- 状态异常或全部关闭时禁用。

“全部下线”：

- 停止已确认属于本项目的 `8775` 公网 Web。
- 禁用或删除固定的 `8775` 防火墙规则。
- 核对 `pythonw.exe`、`launcher.py` 和项目路径后，向对应启动器窗口发送正常关闭消息，使启动器执行自己的 `close()` 清理 AI 网关和代理桥。
- 启动器未正常退出时，只结束证据充分且属于本项目的 `8780`、`7896` 进程。
- 复查 `8775`、`8780`、`7896` 均无项目监听。
- 未知进程仍占用端口时报告冲突，不结束未知进程，也不把状态显示为全部关闭。

### 端口管理

端口表至少显示：端口、监听地址、PID、进程名称、可执行文件、项目归属可信度、健康状态和说明。

面板固定管理三个项目端口。用户可以输入其他端口做只读检查，但不能通过该入口结束未知程序或创建防火墙规则。只有被判定为本项目的进程才显示“停止”操作。

### 版本发布

发布页支持选择 ZIP、填写预期 SHA-256、检查发布包、执行更新、列出回滚点和执行回滚。

检查阶段调用 `scripts\server_release.ps1 -Mode Inspect`，展示发布 ID、Git commit、文件数量、包 SHA-256 和代码聚合 hash。检查只读，不修改当前版本。

更新阶段：

1. 显示本次变更、保护项、影响、备份位置和回滚方法。
2. 用户确认本次具体更新。
3. 执行“全部下线”并确认项目端口停止。
4. 调用 `scripts\server_release.ps1 -Mode Apply` 创建代码回滚点并更新代码和依赖。
5. 展示发布结果和回滚 ID。
6. 保持服务关闭，由用户重新打开启动器、检测并上线。

回滚阶段：

1. 只列出包含有效 `rollback-manifest.json` 的回滚点。
2. 显示目标回滚点、影响和保护项。
3. 用户确认本次具体回滚。
4. 要求所有项目服务停止。
5. 调用 `scripts\server_release.ps1 -Mode Rollback`。
6. 保持服务关闭，由用户重新启动和验证。

面板不得绕过发布脚本对 `.env`、`.venv`、`data`、`images`、`uploads`、`logs`、`staging` 和 `private` 的保护。更新面板自身时，由独立 PowerShell 子进程在当前面板退出后完成替换；不允许运行中的面板覆盖自己。

### 日志与帮助

日志页可以查看面板、Web、AI 网关和发布日志，并提供“打开日志目录”和“打开部署文档”。常见错误应给出直接建议，包括端口冲突、网关未启动、代理链失败、防火墙异常、SHA-256 不匹配和发布包包含保护路径。

面板操作日志写入 `logs\deployment-panel.log`，至少记录时间、动作、检查结果、PID、端口和执行结果。日志写入前必须过滤令牌、Cookie、密码、授权头和包含凭据的代理 URL。

## 进程归属判定

端口号本身不能证明进程属于本项目。归属判断必须综合以下证据：

- PID 和进程创建时间。
- 可执行文件是否为当前项目 `.venv` 中的 Python。
- 命令行是否包含预期入口：`creative_studio.app`、`chat2api\main.py` 或项目代理桥。
- 命令参数或可用的工作目录证据是否指向当前项目。
- 父进程链是否最终指向当前项目的 `launcher.py` 或面板；允许中间存在 `cmd.exe` 或受控包装进程。
- 面板启动的公网 Web 是否存在匹配 PID、创建时间和命令信息的运行状态记录。

证据充分时标记为“本项目，可管理”；证据矛盾时标记为“未知占用”；进程已退出或 PID 被复用时状态记录立即失效。Python 安装位置和版本可以不同，但项目目录内的伪造路径（例如 `.venv-evil`）不能被接受。停止操作执行前必须重新核对证据，不能使用刷新时缓存的 PID 直接结束进程。

归属提示解释：

- “可执行文件不匹配”：旧版本要求固定项目虚拟环境；当前版本允许系统 Python，但仍需要项目目录或项目父进程证据。
- “工作目录不匹配”：没有取得当前项目根目录或对应 `chat2api` 目录的证据。
- “入口命令不匹配”：命令行没有识别到该端口对应的 `creative_studio.app`、`main.py` 或代理桥入口。

面板运行状态文件只能记录非敏感的 PID、创建时间、入口类型和项目根目录。状态文件不能作为唯一归属证据。

## 结果和错误处理

每项检查返回统一结构：检查项、级别、简短结论、证据摘要和建议动作。

- 通过：绿色，条件满足。
- 警告：黄色，不阻止当前动作，例如当前配置不需要代理桥。
- 失败：红色，阻止相关动作。

批量操作按步骤顺序执行。某一步失败后立即停止依赖它的后续步骤，保留已经完成的动作和真实状态，并给出恢复入口。面板不得把部分成功描述为整体成功，也不得在发布失败后自动重新上线。

健康检查设置明确的连接和响应超时。后台任务完成、失败或取消后必须恢复按钮状态。未捕获异常应写入脱敏日志，并在界面显示可理解的错误编号和日志位置，而不是完整堆栈。

## 数据和敏感信息

面板对以下内容只有存在性或只读状态检查权限：

- `data\creative_studio.db`
- `data\images`
- `data\uploads`
- `data\image_job_state`
- `chat2api\.env`

面板不得修改、迁移、删除或打包这些内容。不得把 `.env` 内容、真实令牌、Cookie、密码、完整代理地址或 AI 请求内容写入界面、日志、测试夹具、状态文件、发布包或 Git。

## 测试要求

### 单元测试

系统调用必须通过可替换接口注入。单元测试使用假进程、假端口、假防火墙和假 HTTP 响应，不操作开发电脑的真实防火墙或项目服务。

至少覆盖：

- 全部关闭、本地就绪、公网运行和部分异常的状态判断。
- 已知项目进程、证据不足、证据矛盾和 PID 复用。
- `8775` 被未知程序占用时拒绝上线和停止。
- `8780` 或 `7896` 监听公网地址时判定失败。
- 网关健康但代理链请求失败时不误报完整可用。
- 防火墙规则缺失、字段错误或重复时的处理。
- 按钮前置条件、操作中禁用和失败后的恢复。
- 日志对令牌、Cookie、密码和代理凭据的脱敏。
- 错误 SHA-256、非法 manifest、保护路径和无效回滚点。
- 更新或回滚失败后保持服务关闭并显示恢复信息。

### 集成测试

集成测试使用临时目录、测试进程和非生产端口验证进程检查、健康检查、后台任务及发布脚本适配。默认不得修改真实 Windows 防火墙；防火墙写操作通过替身验证计划命令和参数。

### Windows 人工验收

服务器更新前必须逐项完成：

1. 普通权限启动时只读限制正确。
2. 管理员启动时只出现一次 UAC。
3. 打开启动器且不会重复启动。
4. 启动前检测能识别本地服务和真实冲突。
5. 上线后只有 `8775` 对外监听，`8780` 和 `7896` 保持回环。
6. 本机健康、公网健康、文字生成和单张图片受控验证结果分别记录，不互相替代。
7. 全部下线后项目的三个端口均释放，固定防火墙规则不再放行。
8. 发布包检查、更新、重新启动、回滚和再次启动各执行一次。
9. 数据库、图片、上传目录和 `.env` 在更新与回滚前后 hash 或清单保持一致。

## 发布与文档同步

实施时必须把面板入口、模块和启动批处理加入 `scripts\build_release.ps1` 管理的发布文件列表。不能把运行状态、面板日志、`.env` 或服务器配置打入发布包。

实现完成后同步更新：

- `docs\deployment\public-startup-guide.md`：将日常命令流程改为面板按钮流程，并保留故障恢复命令。
- `docs\project-rules\operations.md`：增加面板作为 Windows 公网上下线入口。
- `docs\project-rules\项目代码地图.md`：登记面板入口和各模块职责。
- `progress.md`：记录实现、验证结果和仍未验证的服务器行为。
- `CHANGELOG.md`：记录用户可见的部署方式变化。

## 维护不变量

后续优化必须保持以下不变量：

1. 手动上线；Windows 重启后不自动恢复公网。
2. `8780` 和 `7896` 永不创建公网放行规则。
3. 未确认归属的进程永不由面板结束。
4. 上线必须先通过启动前检测，再执行切换，再通过上线后检测。
5. 下线定义为关闭 Web、AI 网关、代理桥和启动器，并撤销 `8775` 公网放行。
6. 更新和回滚必须在服务完全停止后执行。
7. 发布和回滚只处理代码，不覆盖运行数据、敏感配置或日志。
8. 面板不展示、记录或打包敏感信息。
9. 健康接口成功不能替代真实文字和图片能力的独立验证。
10. 实际公网部署、服务器更新和真实 AI 验证继续遵守 `AGENTS.md` 的高风险门禁。
11. 上线结果只能显示结构化、脱敏的 PID 和结论，不得显示 `Popen` 对象 repr、完整命令行或环境变量。

## 后续优化顺序

首版稳定后，按实际运维证据评估以下增强，不在首版中提前实现：

1. 将常见故障建议与已知错误编号关联。
2. 增加发布前数据库一致性只读检查和备份状态提示，不自动删除备份。
3. 增加操作历史筛选和诊断报告导出，导出前继续脱敏。
4. 在具备正式域名、HTTPS、访问限制和外部限流方案后，再设计对应状态检查。

每次优化应单独设计、实现和验证，不得通过扩展“任意命令”或“强制结束”能力绕过本规则。
