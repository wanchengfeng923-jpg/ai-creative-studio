# ADR-0002：叙事与展示标签目录同步

- 状态：Accepted
- 日期：2026-09-03
- 决策范围：叙事类和展示类创意定位标签目录、统一标签 prompt 输入和公开项目标签
- Supersedes：无

## 背景

新版 `叙事类标签_重制版.xlsx` 和 `展示类标签.xlsx` 调整了标签选项、分类和定义。叙事类新增“美术风格”模块，且要求它位于“目标人群”之后；展示类目标用户和美术表现风格目录也发生了增删。运行时目录是 `config/creative_tag_options.json`，不能直接读取下载目录中的工作簿。

## 决定

- 以两份工作簿的选项名称、分类、定义和顺序重建 JSON 目录，版本更新为 `tags-2026-09-03-v2`。
- 叙事类目录顺序固定为 `target_audiences`、`art_style`、`player_desires`、`content_forms`、`opening_hooks`、`product_evidences`。
- 叙事美术风格使用 `art_style` 作为统一标签键，最多选择 2 项；它通过现有 `{{creative_tags}}` 注入，不新增 prompt 占位符或修改叙事 prompt 模板。
- 展示目标用户工作簿没有 ID，按分类分配稳定的 `U-*` ID；展示美术风格按风格名称归并重复的参考作品行，并按相关度分配 `AS-S*`、`AS-W*`、`AS-U*` ID。
- 旧项目数据库中的标签字符串不迁移、不删除；前端继续按已有标签兼容显示规则呈现历史值。新目录只影响之后的编辑、保存、指纹和 AI brief。

## 影响

叙事类从 5 组变为 6 组，新增美术风格会参与规范化、生成指纹、统一 prompt 和公开项目投影。展示类关系表保持原有产品卖点到展示内容映射不变。选项定义和分类以工作簿为准，旧名称不再作为新目录选项。

## 验证

契约测试检查目录顺序和数量、统一 prompt 中的叙事美术风格、指纹差异、公开投影以及展示关系完整性；不调用真实 AI、不修改数据库和 `.env`。

## 回滚

代码和配置回滚以本次 Git 提交为边界。回滚只恢复配置和代码，不覆盖运行数据库、图片、上传文件或网关配置。
