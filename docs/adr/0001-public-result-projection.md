# ADR-0001：公开结果采用白名单投影

- 状态：Accepted
- 日期：2026-09-03
- 决策范围：浏览器可见的项目、生成历史、状态、采用结果和展示画面
- Supersedes：无；本 ADR 首次固定公开/私有字段边界，并替代代码中的删除式过滤惯例

## 背景

生成记录、展示方案和逐帧记录需要在服务端保留图片指令、供应商会话游标、本地路径、网关任务标识及内部错误详情。旧实现通过复制内部字典后删除少数字段来形成 HTTP 响应，不同路由的删除清单不一致，旧 `items_json` 和 `snapshot_json` 还可能已经保存私有字段。

## 决定

所有浏览器可见结果统一由 `PublicResultMapper` 从空对象开始，按结果类型的显式白名单重建。history、status、adopt、项目读取、visual item 和 display frame 必须复用该 mapper；未来新增 export 也必须复用同一边界。未知字段默认丢弃，图片 URL 只依据公开 id 和成功状态在应用内生成，不信任内部保存的 URL。

内部错误正文、模型原文、图片指令、会话游标、本地路径、上传存储名和网关任务标识不得进入公开类型。公开失败只包含稳定错误代码、阶段、字段路径、可重试性、trace id 和安全摘要。

旧 raw JSON 不直接公开。一次性 `projection_scrub` 使用同一 mapper 重建历史投影，默认只读 dry-run；写入只允许显式指定的非生产副本，必须先备份，并在无效 JSON、未知结果类型或写后校验失败时中止或回滚。

## 替代方案

- 继续复制字典后逐项 `pop`：拒绝。新增内部字段时会默认泄露，且多个路由容易漂移。
- 在 repository 中永久只保存公开数据：拒绝。图片执行和故障诊断仍需要私有事实，也会把公开契约与存储结构绑定。
- 立即修改真实运行库：拒绝。Phase 0 没有迁移真实用户数据的授权，只提供只读统计和临时副本演练。

## 影响

- 公开契约新增字段必须显式加入 mapper 和递归隐私测试，不能依赖内部 JSON 自动透传。
- 旧数据仍可在内部诊断路径读取，但任何 HTTP caller 都不能直接序列化它。
- deny-by-default 可能遗漏合法的旧前端字段；通过正式前端实际消费字段和旧/新 fixture 的契约测试控制该风险。

## 迁移

Phase 0 将现有公开 caller 切到 `PublicResultMapper`，并用临时 SQLite 验证 scrub 的 dry-run、备份、apply、fixed-point 和恢复。真实 `data/creative_studio.db` 只做只读 dry-run。Phase 5 再根据保留策略决定旧 raw JSON 的期限，不建立永久双读或双写。

## 回滚

代码回滚以本阶段 Git 提交为边界；SQLite 新增列属于加法迁移，可保留并由旧代码忽略。临时副本通过 scrub 创建的 backup 恢复。不得通过恢复 raw 字典直出来回滚公开 mapper，也不得覆盖真实运行库。
