# 权限登录与账号管理设计

## 1. 背景与目标

当前网页服务没有用户、会话或项目归属，所有项目 API 都可直接访问。目标是在不改变创意生成、历史、采用和图片任务合同的前提下，增加互联网威胁模型下的基础认证和角色授权，为后续 HTTPS 公网发布提供正确的应用边界。

本次只交付应用内认证和授权。服务继续监听 `127.0.0.1`；公网绑定、反向代理、HTTPS、域名、外部限流和部署由单独发布变更负责。

## 2. 角色和领域词汇

- **用户（User）**：可以登录工作台的身份记录。
- **管理员（Admin）**：角色为 `admin` 的用户，可管理普通账号并访问全部项目。
- **普通用户（Ordinary User）**：角色为 `user` 的用户，只能访问自己拥有的项目。
- **项目所有者（Project Owner）**：项目的归属用户；现有项目迁移给首个管理员。
- **会话（Session）**：登录成功后由服务端保存、可撤销且带过期时间的登录状态。
- **Bootstrap 管理员**：首次初始化时创建的第一个管理员，不是特殊的永久账号。

## 3. 总体架构

认证逻辑放在独立的 `auth.py`，数据库事务和行转换继续由 `repository.py` 负责，HTTP 路由和响应包络继续由 `app.py` 编排，正式页面在现有 `static/index.html`、`static/app.js`、`static/styles.css` 中增加登录和管理员对话框。

### 3.1 数据表

`users`：

- `id`、唯一规范化 `username`、`password_hash`、`role`、`is_active`、`must_change_password`
- `created_at`、`updated_at`、`last_login_at`

`sessions`：

- 会话令牌哈希、`user_id`、CSRF 令牌哈希
- 创建时间、最后活动时间、空闲/绝对过期时间、撤销时间
- 脱敏的来源 IP 和 User-Agent 摘要

`login_attempts`：

- 按用户名和来源地址的失败次数、窗口起点和锁定截止时间

`audit_logs`：

- 操作者、动作、目标类型/标识、结果、时间和脱敏元数据
- 不保存密码、Cookie、完整请求、完整模型回复或用户文件内容

`projects` 增加 `owner_user_id` 和索引。迁移使用显式 schema 版本和事务；初始化管理员创建与旧项目归属在同一事务中完成。

### 3.2 密码和会话

- 密码使用标准库 PBKDF2-HMAC-SHA256、随机盐和明确迭代参数；哈希格式携带算法和参数，便于未来升级到 Argon2id。
- 密码最少 3 位。管理员重置普通账号时生成一次性临时密码或接收一次性输入，并设置 `must_change_password`。公网部署建议使用更长的随机密码。
- 用户名规范化为小写 ASCII 标识符（长度 3-64，允许字母、数字、`.`、`_`、`-`），避免大小写和同形字符造成混淆。
- 管理员重置普通账号时由服务端生成至少 18 位一次性临时密码，仅在成功响应中展示一次，并设置 `must_change_password`；数据库和日志不保存明文。
- 浏览器保存随机会话令牌的 HttpOnly Cookie；数据库只存 SHA-256 令牌哈希。
- CSRF 使用独立的随机 Cookie 和 `X-CSRF-Token` 请求头；数据库保存其哈希。会话 Cookie 使用 `SameSite=Lax`，CSRF Cookie 使用 `SameSite=Strict`。
- 默认会话空闲 12 小时、绝对 7 天；登录轮换令牌，退出、停用和重置密码撤销相关会话。
- `Secure` 由显式部署配置开启；本机 HTTP 开发保持关闭，公网 HTTPS 发布必须开启。

## 4. API 和授权

认证接口：

- `GET /api/auth/status`
- `POST /api/auth/login`
- `GET /api/auth/me`
- `POST /api/auth/logout`
- `POST /api/auth/password`

管理员接口：

- `GET /api/admin/users`
- `POST /api/admin/users`
- `PUT /api/admin/users/{id}`（停用/启用）
- `POST /api/admin/users/{id}/reset-password`

现有项目、历史、生成、采用、参考文件、视觉项状态、图片读取和重试接口全部要求登录。项目资源统一执行：管理员允许通过，普通用户必须匹配 `owner_user_id`。视觉项和图片通过关联项目反查所有者，防止数字 ID 越权。

状态码约定：未登录 `401`，已登录但无权限 `403`，登录限流 `429`，重复/冲突 `409`，业务输入错误 `400`。失败响应继续使用现有 `{"success": false, "error": "..."}` 包络，并避免资源存在性枚举。

## 5. 初始化和迁移

CLI：

```powershell
python -m creative_studio.auth_cli init-admin --username admin --password-stdin
```

也支持 `CREATIVE_STUDIO_BOOTSTRAP_ADMIN_USERNAME` 和 `CREATIVE_STUDIO_BOOTSTRAP_ADMIN_PASSWORD`，仅在 `users` 为空时读取；成功后不再使用。没有初始化管理员时，服务只提供状态/初始化提示，不开放业务 API。

迁移顺序：备份运行数据；以事务创建认证表；增加 `owner_user_id`；创建初始化管理员；把空所有者项目归属该管理员；提交并记录 schema 版本。失败时回滚事务并拒绝启动业务线程。

## 6. 前端交互

页面先调用认证状态/当前用户接口。未登录只显示登录层，不加载标签、项目或历史；登录后才启动现有 `init` 数据流。管理员显示账号管理按钮和同页对话框；普通用户不可见。所有写请求由统一 `api()` 注入 CSRF Header。

收到 `401` 时停止轮询、清理内存状态并返回登录；收到 `403` 只显示无权限提示。密码修改和强制改密状态阻止业务 API，完成后重新登录。

## 7. 安全控制

- 登录错误使用统一文案；用户名规范化并限制长度。
- 失败尝试按用户名+来源地址限流，成功登录清理窗口；外部公网限流另由反向代理提供。
- 管理员保护：不能停用最后一个管理员，不能把自己降为普通用户。
- 会话查询始终检查用户启用状态和过期/撤销时间。
- 日志和审计只记录必要标识、结果和耗时，禁止秘密和完整内容。
- 静态页面继续可被浏览器下载，但任何业务数据都必须经过认证 API；资源路径继续做目录边界校验。

## 8. 测试和验收

- 临时 SQLite 单测：哈希验证、初始化幂等、迁移归属、会话过期/撤销、锁定、最后管理员保护、项目越权。
- HTTP 集成测试：登录/退出、CSRF、401/403/429、管理员接口和图片/文件 IDOR。
- 前端静态冒烟：未登录不发业务请求、角色入口、会话过期回登录、移动端无横向溢出。
- 回归检查：`unittest`、`node --check static/app.js`、`compileall`、`git diff --check`；不发真实 AI 请求。

## 9. 回滚与后续扩展

代码回滚以认证提交为边界；数据回滚保留当前数据库副本后恢复验证过的备份。未来可在同一用户/会话边界上增加 MFA、邀请、项目共享、审计查询或 OIDC，而不改变现有生成模块。
