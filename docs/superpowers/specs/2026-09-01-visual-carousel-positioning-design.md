# 展示类轮播逐轮创意定位设计

- 日期：2026-09-01
- 状态：设计已获用户确认，待规格审阅
- 范围：正式原生页面的展示类轮播定位与最终生成结果

## 目标

用户选择“多画面轮播”后，可以为固定数量的每一轮画面设置自己的创意定位。第 2～N 轮默认跟随第 1 轮，但用户可以在任意轮次切换为自定义并修改。所有标签在编辑阶段都不强制用户填写；用户未填写的适用标签在最后一次生成请求中由 AI 根据上下文补全。

最终生成仍是唯一的 AI 文字工作入口：第 1、2 步只做本地状态编辑和自动保存，点击第 3 步生成按钮后一次性提交全部上下文、继承关系和用户覆盖值。每套展示方案只生成第 1 轮代表图，逐轮补图不在本次范围内。

## 非目标

- 不修改叙事类生成逻辑。
- 不在标签编辑步骤调用 AI，不新增标签建议或预览接口。
- 不新增轮播专用 SQLite 表，不迁移现有数据库。
- 不把 AI 补全结果自动写回项目当前草稿。
- 不增加逐轮图片生成、逐轮重试或轮播视频渲染。
- 不改变展示类每批 3 套方案、最多 2 批的限制。

## 用户流程

### 第 2 步编辑

`是否轮播` 是唯一必须由用户先选择的结构字段：

- 选择“否”时，隐藏轮播数量、轮播形式和轮次编辑器；保留既有值但不参与生成。
- 选择“是”并指定 `2屏`～`5屏` 时，显示第 1～N 轮标签页。
- 选择“是”并指定“AI决定”时，不显示未知数量的轮次标签页；用户继续编辑全局标签，AI 在最终请求中统一决定 2～5 屏。

2026-09-04 经用户确认，逐轮覆盖字段扩展为六组：主目标用户、玩家欲望、产品卖点、展示内容、视觉母题、动态方案；不包含美术表现风格、语音钩子和三个轮播流程控件。六组在 UI 上均为选填并沿用各自原有数量上限；视觉母题和动态方案默认展开，其余四组默认收起，展开状态按轮次独立保存。空的、适用的标签组交给最终 AI 补全。

第 2～N 轮默认显示“跟随第 1 轮”。用户手动编辑后变成“本轮自定义”，可以恢复跟随。切换“是/否”时保留轮次配置并隐藏，切回“是”时恢复；只有轮播开启时才读取轮次配置。

### 最终生成

点击生成后只发起一次展示类文字生成请求，输入包括：任务说明、产品证据、全局标签、轮播开关、数量模式、轮播形式、固定轮次的继承关系和覆盖值。前面步骤不发起 AI 请求。

AI 处理优先级：

1. 用户明确选择的值是最高优先级约束。
2. 后续轮次未覆盖的字段继承第 1 轮。
3. 第 1 轮为空的适用字段由 AI 选择一次，供仍跟随第 1 轮的轮次共享。
4. 切换为自定义但留空的轮次字段由 AI 单独补全。

“选填”表示用户不必填写，不表示 AI 可以忽略适用字段。AI 应为所有适用的空标签组补出合法值；辅助槽位不需要为了凑满数量而强行填充。非适用字段（例如关闭轮播时的轮播数量/形式）保持空。

## 数据结构

继续使用 `projects.creative_tags_json` 的 JSON 包络，不增加数据库字段。轮播配置在视觉标签中增加一个独立对象，示意如下：

```json
{
  "visual_carousel": ["是"],
  "visual_carousel_count": ["3屏"],
  "visual_carousel_form": ["由弱到强"],
  "visual_carousel_rounds": [
    {
      "index": 1,
      "mode": "base",
      "overrides": {
        "visual_product_selling_points": ["..."],
        "visual_display_contents": [],
        "visual_motif": ["..."]
      }
    },
    {
      "index": 2,
      "mode": "inherit",
      "overrides": {
        "visual_product_selling_points": ["..."]
      }
    }
  ]
}
```

`count_mode` 不必另存为标签：由 `visual_carousel_count` 的值是否为“AI决定”推导。`mode=inherit` 的轮次只保存用户覆盖值；服务端/前端在生成前展开有效输入，不把展开结果回写项目草稿。旧项目没有该对象时按无轮次处理。

AI 补全后的完整标签只保存于本次 generation 的结果快照，不覆盖项目草稿。历史记录因此可以复现该批次最终采用的定位。

## AI 输出

非轮播展示类继续使用现有 `visual.v1` 结构。轮播展示类使用独立版本（建议 `visual.carousel.v1`），每个方案保留现有总体字段和一张代表图 `image_prompt`，并增加：

- `resolved_tags.global`：本方案最终采用的全局适用标签。
- `resolved_tags.frames`：每轮主目标用户、玩家欲望、产品卖点、展示内容、视觉母题、动态方案及来源标记。
- `carousel_frames`：每轮的标题、静态画面描述、核心主体和布局。

来源标记只允许 `user`、`inherited`、`ai`。`image_prompt` 只服务第 1 轮代表图；不描述逐秒脚本、转场或视频过程。固定数量时 `carousel_frames` 必须精确匹配 N；AI 决定时三套方案统一返回同一个 2～5 屏数量。

AI 自动补全的标签必须来自 `config/creative_tag_options.json` 的合法选项；产品卖点与展示内容必须满足现有 `product_display` 关系，主选/辅助数量必须满足配置上限。用户选择的 `visual_carousel` 不得被 AI 改写。

## 结果交互

保留现有三套方案卡、采用、历史和图片状态。轮播方案在卡片内展开查看第 1～N 轮定位；每轮显示最终标签，并用轻量标记区分用户选择、继承和 AI 补全。结果页不直接编辑补全标签，用户回到第 2 步调整后重新生成。每套方案只创建一个现有视觉图片任务，代表第 1 轮。

## 错误处理

- 缺少 `visual_carousel` 时，生成请求直接提示用户先选择“是/否”，不调用 AI。
- 固定轮次数量不匹配、AI 决定数量越界、标签不在配置中、依赖关系失配或返回字段不完整时，整批标记失败，不追加第二次 AI 修正调用。
- 现有图片任务失败/重试状态机保持不变。

## 验证与验收

- 单元测试覆盖轮次规范化、继承展开、开关隐藏恢复、固定/AI 数量校验、合法标签与依赖校验、生成指纹变化。
- 使用脱敏固定 AI 响应夹具验证一次请求即可同时产生补全标签和轮次定位，确认没有前置 AI 请求。
- 回归叙事类、非轮播展示类、项目自动保存、历史、采用替换和图片失败重试。
- 浏览器在 `1280x720`、`390x844` 验证固定轮次、AI 决定、继承切换、结果展开和无横向溢出；不发起真实 AI 文字或图片请求。
- 完成后运行项目规定的 unittest、`node --check`、Python compileall 和 `git diff --check`，并更新 `progress.md`；用户可见行为同步更新 `CHANGELOG.md`。

## 回滚

代码回滚以 Git 提交为边界，不触碰 `data/` 和 `chat2api/.env`。旧项目 JSON 没有轮次对象时继续按既有非轮播/单画面逻辑读取；旧历史记录保留原结构并按兼容分支渲染。
