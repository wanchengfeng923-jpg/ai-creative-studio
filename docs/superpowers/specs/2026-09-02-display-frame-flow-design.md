# 展示类连续画面生成流程设计

## 1. 背景

当前展示类生成把一套方案和完整轮播结果混在一次文字请求中，且轮播提示词还包含旧的 `resolved_tags` 业务要求。本设计将展示类改为“首帧方案 + 按需后续画面”的流程，同时保留叙事类独立路径。

本设计只定义后端业务接口、状态和数据流。创意效果、写作风格、画面规则和转场规则由 GPT 侧配置，代码不复制这些业务规则。

## 2. 目标与非目标

### 2.1 目标

- 不轮播时，每套展示方案只生成一张图。
- 首次请求用一个共享文字会话返回三套展示方案；随后每套方案各自建立新文字会话并生成第 1 张图。
- 首次同时规划该方案的完整画面路线，但只实际生成首帧。
- 三套方案分别建立独立 GPT 会话，用户继续哪套就复用哪套会话。
- 用户点击继续时，系统逐画面规划并生成剩余画面；每张完成后再进入下一张。
- 用户选择 AI 决定数量时，每套方案独立决定 2 至 5 张，并在方案内锁定。
- 后续画面直接生成图片，不再向可见文字会话返回 JSON；图片提示词由锁定路线和完整方案 brief 编排。
- 图片生成失败时自动重试一次，失败方案保留已成功画面并可从失败处继续。

### 2.2 非目标

- 本阶段不设计前端按钮、布局和展示细节。
- 不允许用户编辑或重新规划已经生成的画面路线。
- 不改变叙事类创意的业务规则。
- 不要求 GPT 输出 `resolved_tags`。
- 不把后续画面并行生成。

## 3. 三个提示词接口

### 3.1 叙事类创意

输入至少包含任务类型、任务描述、叙事类标签、产品信息和参考文件名。

输出为五个故事，每个故事包含两个钩子，每个钩子包含三个画面建议。后端只校验数量、字段、非空和 JSON 格式。

### 3.2 展示类首帧方案

输入：

```json
{
  "task_type": "...",
  "task_description": "...",
  "creative_tags": {},
  "carousel_mode": "none | fixed | ai",
  "requested_frame_count": 1,
  "aspect_ratio": "16:9",
  "product_info": "...",
  "reference_files": []
}
```

输出包含三套方案。每套方案包含方案说明、创意来源、锁定的 `frame_count`、视觉连续性规则、完整 `frame_plan` 和 `first_frame`。

规则：

- `carousel_mode=none` 时 `frame_count` 必须为 1，不能推荐后续数量。
- `carousel_mode=fixed` 时 `frame_count` 必须等于用户指定的 2 至 5。
- `carousel_mode=ai` 时每套方案独立返回 2 至 5。
- 首次只为每套方案实际生成 `first_frame`。

图片模型所需的 `image_generation_instruction` 是服务端字段，不进入公开响应和历史接口。

### 3.3 展示类后续画面

输入包含：方案完整信息、完整画面路线、已完成画面、上一张画面信息、待生成画面序号、视觉连续性规则和画幅。上一张实际图片由图片生成适配器接收。继续操作不调用可见文字聊天接口，直接提交图片生成任务。

每次后续调用只生成一个待生成画面，输出只包含该画面的：

```json
{
  "frame": {
    "frame_index": 2,
    "content": "当前画面内容",
    "transition_from_previous": "从上一画面如何承接",
    "transition_to_next": "如何承接到下一画面",
    "ending_note": null,
    "image_generation_instruction": "服务端图片生成字段"
  }
}
```

后续响应不重复方案说明、创意来源和整体路线。最后一张使用 `ending_note` 表达收束，不要求下一张转场。
`transition_to_next` 在最后一张必须为 `null` 或省略；服务端不得要求模型虚构下一张画面。

## 4. 业务流程

### 4.1 不轮播

```text
共享首帧规划提示词 -> 三套方案和路线
  -> 三套方案各建立独立会话并生成第1帧
  -> 三张首图 -> 返回完整方案和首图 -> 完成
```

### 4.2 固定数量或 AI 决定数量

```text
共享首帧规划提示词
  -> 三套方案各建立独立 GPT 会话并生成第 1 张
  -> 用户点击某套方案继续
  -> 复用该方案会话规划剩余画面
  -> 按序生成第 2 张、第 3 张……最后一张
```

用户一次点击启动剩余画面生成，但后端必须对每个画面分别调用后续提示词，并等待当前画面的文字和图片都成功后，才能提交下一张。同一方案始终只有一个运行中的继续操作；重复点击返回已有操作状态。三套方案之间没有连续性依赖，首图可以并行生成。

## 5. 会话和连续性

首次请求可以一次返回三套方案，但该共享会话只负责方案和路线。随后服务端为每套方案建立一个独立 GPT 会话，并注入：

- 方案完整信息
- 完整 `frame_plan`
- 第 1 张实际图片
- 第 1 张实际画面信息

每套方案仍在独立文字会话中生成并锁定首帧上下文；后续画面沿用该方案的路线和会话元数据，但不再发送可见 JSON 规划消息。图片生成请求提供完整方案 brief，并单独提供上一张实际图片作为 `ref_assets`。

目标是保持创意逻辑、关键视觉元素和转场关系连续，不承诺像素级一致。

会话创建和继续操作必须幂等：同一方案只创建一个会话，并持久化 `conversation_id` 和 `parent_message_id`；继续接口直接复用该游标，不再依赖额外的确认消息。服务端锁定 `frame_plan` 和视觉连续性规则；没有编辑或重新规划路线的接口。上一张实际图片通过图片适配器支持的受控图片输入传递，不向模型传递本地文件路径。

## 6. 后端数据模型

### 6.1 方案级

```text
scheme_id
title
creative_summary
creative_sources
frame_count
visual_continuity_rules
frame_plan
conversation_id
parent_message_id
scheme_status
```

### 6.2 画面级

```text
frame_index
planned_content
actual_content
transition_from_previous
transition_to_next
ending_note
image_status
image_path
attempt
failure_code
failure_message
```

`image_generation_instruction` 只保留在服务端内部对象或受保护的任务数据中，不进入浏览器历史响应。

## 7. 状态和失败处理

方案状态：

```text
ready -> generating -> ready
                    -> blocked
                    -> completed
```

画面状态：

```text
pending -> generating -> success
                     -> retrying -> success
                                  -> failed
```

- 首次请求等待三套首图分别进入 `success` 或 `failed` 后返回；允许部分成功。首图失败只影响对应方案，其他方案正常返回，失败方案可单独重试。
- 每个画面图片任务在一次生成操作内自动重试一次；自动重试仍失败则停止该方案后续画面，保留已成功画面，并将方案置为 `blocked`。
- 后续图片提示词或图片任务失败时不推进下一张，当前画面保持可恢复状态；用户再次继续时从该画面重试。
- 人工恢复只从第一个未成功画面开始。每次自动重试和人工恢复都递增 `attempt`，不能由旧任务覆盖新尝试。
- 所有计划画面成功后，方案标记为 `completed`，不再接受继续生成。

## 8. 后端接口边界

- `app.py` 只处理 HTTP、权限、请求/响应包络和错误映射。
- `generation_service.py` 编排方案、会话、画面顺序和持久化。
- `prompting.py` 只负责将结构化输入交给 GPT 配置，不内置创意业务规则。
- `model_client.py` 只负责通用文字模型会话。
- `image_jobs.py` 只负责按顺序提交图片任务、重试和状态同步。
- `repository.py` 保存方案、画面、会话和任务状态，是事实源。

对外业务接口至少包括：

- 选择方案并幂等创建独立 GPT 会话；
- 继续生成选中方案的下一个及后续画面；
- 重试失败的首图；
- 从失败画面恢复后续串行生成；
- 查询方案、画面、会话和图片任务状态。

接口继续使用现有 `success/error` 包络；重复继续操作、路线已完成或方案未选择时返回可操作的状态冲突错误。历史响应只返回公开方案、画面状态和图片引用，过滤 `image_generation_instruction`、完整模型消息和本地路径。

## 9. 验收标准

1. 不轮播每套方案只有一张图，且不出现数量推荐或继续生成状态。
2. 固定数量时所有画面数量等于用户选择值。
3. AI 决定时三套方案可分别返回不同的 2 至 5 张数量。
4. 首次显示三套方案各自的首图和完整画面路线。
5. 三套方案各自建立独立首帧会话；继续某套方案时沿用该方案上下文并直接进入图片生成。
6. 后续画面按顺序生成，图片模型使用完整方案上下文和上一张实际图片，不产生可见 JSON 文字回复。
7. 后续返回不重复方案说明和创意来源。
8. 单张图片失败最多自动重试一次，失败后可从该画面继续。
9. `image_generation_instruction` 不出现在浏览器响应。
10. 叙事类路径和现有工作台 API 保持兼容。
