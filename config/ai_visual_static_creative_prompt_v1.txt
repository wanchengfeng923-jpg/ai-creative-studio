================ MODULE 00｜接口要求 ================

根据输入生成《剑侠传奇》展示类广告的三套非轮播、单核心静态画面创意路线。

输入：
- 任务类型：{{task_type}}
- 任务描述：{{task_description}}
- 展示类标签：{{creative_tags}}
- 目标画幅：{{aspect_ratio}}
- 产品信息：{{product_evidence_summary}}
- 参考文件名：{{reference_file_names}}

只输出一个合法 JSON 对象。根对象只能包含 items，items 必须恰好包含 3 个对象。不要输出前言、分析、评分、URL、Markdown 代码围栏、思维链或其他说明。

================ MODULE 10｜业务上下文 ================

《剑侠传奇》是一款经典中国武侠回合制手游。可使用门派、侠客、师徒、正邪、江湖关系、装备成长、角色收集、技能属性和阵容等语义，但具体能力、数值、奖励、活动、版本和系统名称只有在产品资料确认后才能当作事实。

核心受众约 25 至 40 岁，男性居多，对经典武侠、老武侠游戏、门派和侠客关系有基础认知。画面要快懂、主体明确、比例可信、层级清楚、留白有效。

这是展示类广告，不是剧情、逐秒脚本、连续镜头或轮播规划。一张图必须独立回答：看到了什么、它证明了什么、为什么值得继续看。每案至少保留《剑侠传奇》游戏名或 Logo 线索，以及一个明确的武侠语义锚点。

================ MODULE 20｜创意生成 ================

以下过程只在内部执行，不输出思维链：

1. 找出任务真正要展示的主资产，区分产品价值和风格形容词。
2. 将信息分为 confirmed、inferred、to_confirm；不确定的玩法、数值、福利、活动和能力不得伪装成事实。
3. 内部生成至少 8 个“第一眼看到了什么值得停一下”的微型 idea。可借用界面、商品陈列、报纸、监控、手机照片、排行榜、地图、档案、对照表等熟悉观看结构，但不要先套固定模板。
4. 让产品资产成为事件：如果拿掉产品证据后只剩漂亮画面，淘汰该 idea。
5. 把 idea 压成目标画幅缩略图。必须依赖运镜、转场、音效、前一张或后一张才能理解的候选淘汰。
6. 去掉只改变角色、配色、字体、材质、文案或装饰的重复方案。
7. 先决定合适的媒介或制作方式，再补视觉执行；不要只写“国风、高级、震撼”等风格标签。
8. 补齐产品证据、素材状态、缺口、风险、文案和图片执行指令。

================ MODULE 30｜筛选规则 ================

内部按任务与受众适配 25%、产品事实与证据 20%、一眼可懂 20%、机制差异 20%、素材与制作可行性 15% 收敛，不输出分数。三案必须是不同的核心观看关系，而不是同一创意换皮。

直接淘汰：依赖动态才能理解；只有口号没有产品证据；编造玩法、数值、奖励、活动、角色能力、版本承诺或投放效果；借用其他品牌身份；元素过多导致主体、证据和文案失去层级。

输出顺序为：最值得优先验证的方案、不同机制的第二验证路径、风险或素材依赖较高但仍值得制作的备选方案。

================ MODULE 40｜执行约束 ================

- 一张图独立成立，禁止用“随后、接着、然后、下一幕、镜头切换、逐渐、变成”等时间过程补足理解。
- 默认不使用角色中央站立、图标环绕、对称神坛、无意义光柱、粒子、烟雾、能量环和复杂花纹；任何装饰都必须服务创意机制、产品证据或阅读层级。
- 主文案只承担一个冲突或价值，建议 4 至 16 个汉字；辅助文案建议不超过 32 个汉字。
- 不擅自添加下载、登录、福利、限时、排名、数值、版本、概率或收益承诺。
- 产品资料是事实来源；标签、行业惯例和参考作品不能替代产品确认。参考文件名不等于已读取文件内容。
- 借鉴参考对象的观看结构、信息组织或媒介机制，不继承对方的 Logo、品牌名、角色身份和世界观标识。
- image_generation_instruction 只写静态图片执行：画幅、媒介、主体、空间关系、产品证据、文案留白、颜色/材质和负面限制；不写动态、镜头运动、音效、时间线或投放效果。未确认的文字、数值、Logo 细节和 UI 必要时写“预留清晰文字区，由后期排版”。

================ MODULE 50｜字段写法 ================

creative_summary 说清画面发生了什么以及证明了什么；audience_tension 只保留一个用户欲望或矛盾；product_value 只绑定一个主价值；visual_mechanism 描述替换、缺失、对照、暴露、越界、聚集等具体关系；confirmed 是已确认事实；inferred 是表现假设；to_confirm 是制作前缺口；visual_event 是静态停留事件；hero_subject 是真正主角，不默认人物居中；composition 交代大小、位置、遮挡、对照、留白和文案区域；product_proof 必须是可见证据；review 只写停留理由、制作价值和一个最早验证动作。

不要输出思维链，只返回经过筛选的三套方案、证据状态和执行信息。
