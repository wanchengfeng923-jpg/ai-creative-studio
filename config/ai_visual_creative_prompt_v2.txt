根据输入生成展示类广告的首帧方案。

输入：
- 任务类型：{{task_type}}
- 任务描述：{{task_description}}
- 展示类标签：{{creative_tags}}
- 目标画幅：{{aspect_ratio}}
- 产品信息：{{product_evidence_summary}}
- 参考文件名：{{reference_file_names}}

只输出一个合法 JSON 对象。根对象只能包含 items，items 必须恰好包含 3 个对象。不要输出前言、分析、评分、URL、Markdown 代码围栏或其他说明。所有要求字段都必须存在且符合类型。

严格使用以下结构：
{
  "items": [
    {
      "title": "方案标题",
      "creative_summary": "方案整体创意说明",
      "creative_sources": ["采用的创意来源或原创依据"],
      "frame_count": 1,
      "visual_continuity_rules": ["该方案后续画面必须保持的视觉连续性规则"],
      "frame_plan": [
        {"index": 1, "description": "第1张画面路线"}
      ],
      "first_frame": {
        "index": 1,
        "content": "第1张实际画面内容",
        "image_generation_instruction": "仅供服务端图片模型使用的首帧生成指令"
      }
    }
  ]
}

数量规则：
- 由 carousel_context 提供画面模式和数量约束。
- none 时每套方案的 frame_count 必须为 1，frame_plan 只能有第1张。
- fixed 时每套方案的 frame_count 必须等于用户指定的 2 至 5，frame_plan 必须连续覆盖全部序号。
- ai 时每套方案独立决定 2 至 5 张，三套方案可以不同；数量确定后锁定。
- 首次只实际生成 first_frame，但必须返回完整 frame_plan。

内容规则：
- creative_summary 和 creative_sources 解释方案，不返回逐帧脚本。
- frame_plan 只描述每张画面的内容路线；不要输出运镜、音效或时间轴。
- first_frame.content 只描述静态首帧及其产品证据。
- image_generation_instruction 只描述静态图片生成，不得包含随后、接着、然后等时间过程；该字段是服务端隐藏字段，不应出现在浏览器响应或公开历史。
- 三套方案的第一眼创意机制应有实质差异，视觉风格由 GPT 侧配置决定。
- 共享规划阶段的 first_frame 是独立方案会话的首帧草稿；服务端会在每套方案的新会话中重新生成实际首帧。
