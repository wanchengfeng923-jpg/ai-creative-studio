「根据这些输入，生成展示类广告创意」

为每套方案锁定连续画面路线。
输入：
- 任务类型：{{task_type}}
- 任务描述：{{task_description}}
- 展示类标签：{{creative_tags}}
- 目标画幅：{{aspect_ratio}}
- 产品信息：{{product_evidence_summary}}
- 参考文件名：{{reference_file_names}}
- 画面模式和数量约束：{{carousel_context}}

只输出一个合法 JSON 对象。根对象只能包含 items，items 必须恰好包含 3 个对象。不要输出前言、分析、评分、URL、Markdown 代码围栏或其他说明。不要输出 resolved_tags、carousel、carousel_frames 或任何未声明字段。

严格使用以下结构：
{
  "items": [
    {
      "title": "方案标题",
      "creative_summary": "方案整体创意说明",
      "creative_sources": ["采用的创意来源或原创依据"],
      "frame_count": 3,
      "visual_continuity_rules": ["该方案后续画面必须保持的视觉连续性规则"],
      "frame_plan": [
        {"index": 1, "description": "第1张画面路线"},
        {"index": 2, "description": "第2张画面路线"},
        {"index": 3, "description": "第3张画面路线"}
      ],
      "first_frame": {
        "index": 1,
        "content": "第1张实际画面内容",
        "image_generation_instruction": "仅供服务端图片模型使用的首帧生成指令"
      }
    }
  ]
}

数量规则：
- none 时每套方案 frame_count=1，不能推荐后续数量。
- fixed 时每套方案 frame_count 必须等于用户指定的 2 至 5。
- ai 时每套方案独立决定 2 至 5 张，三套方案可以使用不同数量；数量确定后锁定。
- frame_plan 必须从 1 开始连续覆盖 frame_count；首次只实际生成第1张图片。

内容规则：
- creative_summary、creative_sources 和 visual_continuity_rules 描述方案级规则。
- frame_plan 只描述每张画面的内容路线，不写逐秒脚本、运镜或音效。
- first_frame.content 只描述静态首帧及产品证据。
- image_generation_instruction 只描述静态图片生成；它是服务端隐藏字段，不进入浏览器响应和公开历史。
- 共享规划阶段的 first_frame 是每套方案的首帧执行指令；服务端直接把该私有指令交给图片模型生成首帧，不再创建独立的文字首帧会话。
