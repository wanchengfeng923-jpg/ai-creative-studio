# UI 重设计原型变更卡

Status: implemented-prototype

## 目标

- 变更名称：AI 创意工作台 UI 信息架构重设计
- 谁使用：在 Windows 本机创建、生成、比较和采用游戏创意方案的内容人员
- 要解决的问题：现有页面把项目、输入、标签和结果纵向堆叠，标签数量增加后主流程被淹没，生成结果难以持续比较
- 期望结果：通过三个结构明显不同的可点击假数据原型，选定正式页面的信息架构方向

## 范围

- 本次要做：三种布局、统一设计系统、假项目/假方案、关键点击状态、变体切换和视觉 QA
- 本次明确不做：接入真实 API、写数据库、调用 AI、上传文件、登录、权限、部署或迁移前端框架
- 是否改变数据库、API、提示词、模型、端口或权限：否

## 验收

- 给定输入：打开 `/ui-prototype.html?variant=A`，通过底部切换器或左右方向键切换 A/B/C
- 应出现的页面或接口结果：三个变体均能展示项目导航、展示/叙事模式、创意配置、方案结果和采用动作
- 数量/字段/状态要求：展示类固定展示 3 套假方案；状态变化在原型底部显式显示；刷新后重置
- AI 输出质量检查：不适用，原型不调用 AI
- 失败时应看到的提示：原型交互使用本地 toast，不向后端提交

## 风险和回滚

- 可能影响的数据或用户：无真实数据写入；仅新增静态原型文件
- 是否需要备份：不需要
- 回滚方式：删除 `static/ui-prototype.*` 和本变更卡
- 必须暂停的情况：发现需要覆盖现有未提交前端改动，或需要连接真实写接口
